figures — where a notebook’s figures go¶

Each notebook writes into one folder beside it, named after it, created relative to the working directory — the same rule the study lookup and RESULTS_DIR follow:

from calculations.figures import results_dir, save_figure

FIGS = results_dir("Proposal")            # -> Proposal-results/
save_figure(fig, "Level1_Perfect_Metal", FIGS)

The sensitivity plotters in sensitivity — regime-stratified sensitivity analysis all return their figure, so they wrap directly — including the ones that return None for a plot they declined to draw, which save_figure treats as a no-op rather than an error.

Where a notebook’s figures go.

Each notebook writes into one folder beside it, named after it:

Guo_etal_2025/
├── Proposal.ipynb
└── Proposal-results/        Level1_Perfect_Metal.png, ...

The folder is resolved against the WORKING DIRECTORY, which for a correctly launched notebook is its own study folder — the same rule RESULTS_DIR = "sa_results" and the study_config.py lookup already follow. Notebooks call calculations.config.assert_study_is_local() in their first cell, so a kernel started in the wrong place fails there, before anything is written to the wrong study.

Usage, in the notebook’s first cell:

from calculations.figures import results_dir, save_figure
FIGS = results_dir("Proposal")

and then, wherever a figure is finished:

save_figure(fig, "Level1_Perfect_Metal", FIGS)

The sensitivity plotters in calculations.sensitivity all return their figure, so they wrap directly:

save_figure(plot_givendata_results(gd, reg, 'flux', PARAMS), f"givendata_{reg}", FIGS)
calculations.figures.RESULTS_SUFFIX = '-results'¶

Appended to a notebook’s name to make its results folder.

calculations.figures.DPI = 450¶

Raster resolution. Was 300, copied from the plt.savefig calls this module replaced. Raised to 450 for sharper figures on a high-density display.

There is a ceiling. Matplotlib refuses an image above 2**16 px in either direction, which at 450 dpi is 145.6 inches – down from 218 at 300 dpi. That is normally vast next to a 14-inch figure, but bbox_inches=”tight” sizes the output from the ARTISTS, not from figsize, so one annotation on a near-flat log axis can ask for thousands of inches. It has happened: the Level 4 grain-size panel demanded 7415.

calculations.figures.VECTOR_FORMAT = 'pdf'¶

Written beside the PNG, sharp at any zoom. PDF rather than SVG because these figures carry scatter and parallel-coordinate plots with thousands of elements, which SVG renders slowly and stores verbosely. Set to None to write the raster alone.

calculations.figures.INLINE_FORMAT = 'retina'¶

Inline display density. Jupyter embeds a figure at matplotlib’s default 100 dpi, roughly a quarter of the pixel density of a current display – which is why figures look soft IN THE NOTEBOOK while the saved PNG, written at DPI above, is sharp. The two are separate settings and only this one affects what you see while working.

calculations.figures.TEXT_STYLE = {'axes.labelweight': 'bold', 'axes.linewidth': 1.4, 'axes.titleweight': 'bold', 'figure.titleweight': 'bold', 'font.weight': 'bold', 'legend.edgecolor': '0.55', 'legend.framealpha': 0.95, 'xtick.major.size': 6.0, 'xtick.major.width': 1.4, 'xtick.minor.width': 0.9, 'ytick.major.size': 6.0, 'ytick.major.width': 1.4, 'ytick.minor.width': 0.9}¶

Weight and frame settings applied through rcParams rather than at the call sites. The notebooks pass an explicit fontsize= to every label – which is why the sizes live in PLOT_STYLE – but they pass no fontweight, so rcParams is the only lever that reaches them, and it reaches all of them at once.

calculations.figures.apply_text_style(overrides=None)[source]¶

Make every figure’s text bold and its axes frame heavier.

Applied on import for the same reason as the inline format: every notebook already imports this module, so there is one place to change and nothing to keep in sync across the four studies.

Sizes are NOT set here. They come from PLOT_STYLE in model_config, because the notebooks pass fontsize= explicitly at each call and an explicit argument beats an rcParam.

calculations.figures.results_dir(notebook, base=None)[source]¶

The results folder for notebook, created if it does not exist.

Parameters:

  • notebook (str) – The notebook’s name, with or without the .ipynb extension. Case is kept, so the folder sorts next to the notebook it belongs to.

  • base (str or pathlib.Path, optional) – Where to put it. Defaults to the working directory — the study folder.

Returns:

The folder. Safe to call repeatedly; it does not clear what is already there.

Return type:

pathlib.Path

calculations.figures.save_figure(fig, name, folder=None, dpi=DPI, close=True, verbose=False, vector=VECTOR_FORMAT)[source]¶

Write fig into folder as a PNG and a vector copy, and close it.

Parameters:

  • fig (matplotlib.figure.Figure or None) – None is accepted and does nothing. The sensitivity plotters return it for a plot they declined to draw — plot_givendata_results when a regime was skipped, plot_regime_comparison_heatmap on an empty matrix — and wrapping those calls must not turn a skipped plot into a crash.

  • name (str) – Filename without extension. .png is appended unless already present.

  • folder (str or pathlib.Path, optional) – Defaults to the working directory, but pass the results_dir you made in the first cell — that is the point of this module.

  • dpi (int) – Raster resolution, defaulting to DPI.

  • vector (str or None) – Extension of a vector copy written beside the PNG, defaulting to VECTOR_FORMAT. None writes the raster alone. The vector file carries no dpi: it is resolution-independent, which is the point.

  • close (bool) – Close the figure once written. On by default: a notebook run saves dozens of figures and nothing else closes them, so they would all stay open for the life of the kernel. The figure has normally been displayed by the plotter’s own plt.show() before this is called, so closing costs nothing visible.

Returns:

Where the PNG was written, or None if there was no figure. The vector copy sits beside it with the same stem; the PNG path is returned because callers and tests treat it as the figure’s identity.

Return type:

pathlib.Path or None
