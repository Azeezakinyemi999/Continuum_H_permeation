Parameter map¶

One quantity, many names. The metal’s diffusivity is called D at Level 1, D_m at Level 1+L6, D_lattice at Level 4, D_metal inside a properties dict, and D_ref in the study configuration — five spellings of one number, and that is before the sensitivity analysis renames the wall thicknesses again.

That is survivable. What is not survivable is the reverse: a single name carrying more than one meaning. thickness is the metal in Level 1 — the perfect metal and the oxide in Level 2 — the oxide layer. f_gb is a volume fraction inside the metal in one place and an area fraction of oxide defects in another, two quantities that differ by more than two orders of magnitude. Nothing errors when those are confused.

This page inventories both, and proposes one canonical name per quantity.

Warning

The canonical names below are a PROPOSAL, except where marked ✅.

Every unmarked name in a “canonical” column is what a quantity would be called under a unified scheme; the “replaces” column holds the name that is real today and that you must use. A ✅ marks one that has since been adopted, and for those the canonical name is the real one.

Adopted so far: the three model switches in section G; f_gb_defect, data_pressure_range, crack_thickness_ratio and gb_diffusivity_ratio; and the thickness function parameters. Each was taken because the short name meant two different things in two places, not for tidiness. alpha and beta in calculations.surface_kinetics are left alone on purpose: they are the permeances the theory chapters derive under those symbols.

How to read it¶

Three naming layers. The same physical quantity is named independently at each, and a rename has to cross all three to be complete:

layer

where it lives

function argument

the positional parameters of each level’s entry point

dict key

inside oxide_props, metal_props, microstructure_params, trap_list entries and the defect configuration

study configuration

CONDITIONS, METALS, OXIDES, MICROSTRUCTURE, OXIDE_DEFECTS, and the flat DEFAULT_PARAMS_LEVEL5 / DEFAULT_PARAMS_LEVEL5L6 the sensitivity analysis varies

Three suffixes, used consistently in the proposal. A bare name is the value at the operating temperature; _ref is the value at the reference temperature; _energy or _enthalpy is the Arrhenius exponent that connects them. The current code blurs this — D_ref and D_lattice are related but genuinely different numbers, and no present naming makes that visible.

I. Collisions — one name, more than one meaning¶

This is the half that is a defect rather than a tidiness problem. An alias costs a reader a moment; a collision silently produces the wrong number.

current

splits into

why it must split

thickness ✅ done (parameters)

metal_thickness · oxide_thickness · layer_thickness

the metal in calculate_simple_metal_flux and calculate_defective_metal_flux, the oxide in molecular_diffusion_flux and calculate_oxide_resistance, and genuinely generic in fick_flux, which is applied to both layers. All ten declarations renamed — seven metal, two oxide, and fick_flux to layer_thickness. The dict key is deliberately left as thickness: inside metal_props['thickness'] the dict already says which layer it is, so it was never the ambiguous half, and renaming it would have reached 112 notebook sites for no gain

f_gb

metal_gb_volume_fraction · oxide_gb_area_fraction

a volume fraction inside the metal against an area fraction of oxide defects. For the shipped studies they differ by more than two orders of magnitude

n_points ✅ done (parameters)

n_profile_points · n_points (config, kept)

the sensitivity analysis’s samples per axis against the wall discretisation, whose default differs per level. The thirteen function parameters are now n_profile_points; the config key stays n_points, because once the other meaning is gone there is nothing left for it to collide with, and the notebooks read it 200 times

beta

metal_permeance · oxide_gb_diffusivity_ratio

a permeance carrying units in calculations.surface_kinetics, a dimensionless ratio in calculations.permeability

alpha

oxide_permeance · gb_diffusivity_ratio

the same problem, for the other layer

T_ref

four scoped reference temperatures

one name in four dicts. The flattened sensitivity layer already splits it correctly; the nested configuration relies on scope

include_gb_* ✅ done

enable_gb_enhancement · enable_gb_as_trap

near-identical names, opposite physics. Enhancement speeds diffusion up through a fast path; trapping slows it down by holding hydrogen still. Renamed; no notebook referenced any of the three, so the change was contained to calculations/, the four study files and one test

pressure ranges

sweep_pressure_range · data_pressure_range

P_range is the span the sensitivity analysis sweeps; pressure_range is the window the source data are valid over. Unrelated, nearly homonymous

117 distinct names in use today → 86 under the proposal. Thirty-one eliminated as aliases, eight split because they carry more than one meaning.

One rename path fails silently¶

Danger

A model wrapper absorbs an unrecognised parameter name without complaint. level5_model_wrapper copies the defaults and applies .update(params_dict), so a key that no longer exists is stored and then never read. Verified: passing a stale name alongside no other change returns a flux bit-identical to the baseline, with no error and no warning.

check_against_config does not close this. It demands a default for every swept range, and it cross-compares the Level 5 and Level 5+L6 preset blocks against each other — but it never checks that a preset key exists in DEFAULT_PARAMS. A rename applied consistently to both preset dicts and not to the defaults passes clean.

The exposure is the regime presets: 36 distinct parameter names pinned across the three Level 5+L6 regimes, 28 across the Level 5 regimes. None are stale today. A preset that silently stops pinning its parameter does not fail a test — it quietly degrades a targeted regime scan into an untargeted one, which is the whole basis of the regime-stratified workflow.

Eight defaults have no sweep range at all, so even the working half of the check does not cover them: D_eff_method, P_downstream, T_ref_metal, T_ref_oxide, gb_type, grain_shape, include_gb_enhancement, include_trapping.

Suggested order¶

  1. Add a preset-key guard to check_against_config — assert every regime preset key exists in the corresponding defaults. A few lines, passes on the configuration as shipped, and converts the only silent failure mode into a loud one. Worth doing whether or not a rename follows, because a typo in a preset name is indistinguishable from a stale one today.

  2. Fix the collisions in section I. Small, self-contained, and the only part that can silently produce a wrong number. It does not require touching the hundreds of alias sites.

  3. The alias rename in sections A–H, if at all. Cheapest at the solver layer, most expensive at the configuration layer, and of no scientific consequence — this is readability, weighed against churn in 25 notebooks.
